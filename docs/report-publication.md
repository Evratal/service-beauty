* Какую запись сверял: 28 октября 2026, 10:00, маникюр с покрытием, мастер Анна Ковалева (демо-запись Ирины из seed)

## Вход через Яндекс

* Что показал экран согласия Яндекса: — (проверка на стороне пользователя: нужно нажать «Войти через Яндекс» на https://nogotochki.portfolio-evratal-1.ru и согласиться; экран отдаётся с client_id приложения «Ноготочки»)
* Роль в базе: `client` (внешний пользователь получает роль клиента; в коде `src/routes/auth.js` провайдеру выдаётся роль client)
* Поле пароля: пустое (в `users.password_hash` пишется пустая строка, вход по паролю для такого аккаунта отсекается)
* Поле provider: заполнено — `yandex` (и `provider_id` — идентификатор аккаунта Яндекса)
* Как смотрел базу: команда в терминале контейнера — `docker exec <container> node -e "…select id,email,provider,provider_id from users…"`
* Повторный вход: должен попасть в тот же кабинет, новой строки нет — обеспечивается уникальным индексом `idx_users_provider_identity` по (provider, provider_id). Фактический результат повторного входа нужно отметить после первого входа через Яндекс.

Базовый адрес возврата задан в переменной окружения `YANDEX_REDIRECT_URI=https://nogotochki.portfolio-evratal-1.ru/api/auth/yandex/callback` и совпадает с адресом, зарегистрированным в кабинете приложения Яндекса.

## Разбор одной поломки публикации

* Что видел: после первого деплоя каталог отвечал ошибкой «Студия не настроена. Выполните npm run seed.» — на боевом адресе были страница и стили, но ни услуг, ни мастеров, ни слотов; на своём компьютере всё работало.
* Чем оказалось: в Docker-образ не попадала папка `scripts/` (Dockerfile копировал только `package.json`, `src`, `public`, `migrations`), а миграции при старте создавали пустую базу — seed никто не запускал. Более того, на старте контейнера выполнялся только `node src/server.js`, то есть даже скрипты миграций внутри контейнера не запускались вовсе.
* Как починил: в Dockerfile добавил `COPY scripts ./scripts` и заменил команду запуска на цепочку `node scripts/migrate.js && node scripts/seed.js && node src/server.js`. Скрипт seed идемпотентный: при непустой базе он выходит сразу, поэтому повторные деплои данные не трогают.
* Как убедился, что починилось: прогнал ту же последовательность локально на чистой базе (`migrate → seed → start`), затем удалил образ и задеплоил заново — на боевом адресе `GET /api/services` вернул 6 услуг, `GET /api/masters` — 3 мастера, запись клиента создалась и пережила пересборку (Redeploy): после перезапуска контейнера в админке остались все записи, включая отменённую.
* Чем эта поломка отличалась от тех, что случались на своём компьютере: локально папка `scripts/` просто лежит рядом и запускается руками (`npm run seed`), поэтому её отсутствие незаметно. В контейнере есть только то, что явно скопировано в Dockerfile, и никто не запускает npm-скрипты — ошибка проявилась только после публикации.

Дополнительно при подготовке публикации: `yandex-creds.txt` с секретом приложения Яндекса оказался в индексе Git и уехал в публичный репозиторий. Файл убран из отслеживания и добавлен в `.gitignore`; сам секрет из истории Git не удаляется, поэтому его нужно перевыпустить в кабинете oauth.yandex.ru.

## Решение по персональным данным

* Режим работы сервиса: учебный на вымышленных данных
* Что сделано, чтобы не собирать чужие данные: плашка на главной странице (под контентом, видна на всех экранах): «Учебный проект. Сервис работает на демонстрационных данных: услуги, мастера, записи и контакты вымышленные. Не вводите здесь реальные персональные данные.» В базе заведены только демо-пользователи студии (администратор, три мастера, три клиента с адресами @example.com); адрес сервиса давали только для проверки курсовой работы.
* Что будет с сервером и данными после защиты: сервер будет удалён вместе с томом `sidr1ae3wxiti5uze890rhqc-nogotochki-data`, в котором лежит файл `app.db` — то есть база удаляется целиком. Домен `nogotochki.portfolio-evratal-1.ru` удаляется из панели Coolify, DNS-запись поддомена можно удалить в зоне `portfolio-evratal-1.ru`.
